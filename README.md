## 这是什么

校园里的机会分散在公众号、群聊、海报和口头通知里：截止时间藏在图片中、地点临时变更、有的需要审核、
有的来源可疑。新生尤其容易错过或踩坑。

**CampusRadar** 把校园活动、竞赛、招募、志愿、学习小组与资料聚合到一个可在浏览器离线运行的站点里，
重点解决四件事：

| 能力 | 具体表现 |
| --- | --- |
| **发现** | 今天、明天、近期可参加的机会一屏可见，支持搜索 / 五类筛选 / 智能排序 |
| **理解** | 来源、适用对象、报名截止、是否需要审核、是否有补充通知、信息是否缺失、是否存在风险 |
| **参与** | 收藏、报名 / 意向登记、设置提醒、加入日历、标记不感兴趣、复制信息 |
| **发布** | 学生可自主发布约球 / 搭子 / 招募 / 交流信息，并进入发现、筛选、日历等完整流程 |

所有判断都**只使用题目已提供的信息**：凡未注明的一律显示「未注明，请以主办方通知为准」，不做补全或猜测。

## 快速开始

```bash
# 方式一：直接双击（推荐）
index.html

# 方式二：任意静态服务器（可选）
python -m http.server 8000     # 然后访问 http://localhost:8000
npx serve                      # 或使用任意静态服务器
```

无需 `npm install`、无需打包、无需联网。首次访问会自动进入新生引导页（`#/onboarding`），
也可以在地址栏直接输入任意路由，例如 `#/detail/01`。

想跑自检（可选，需要 Node）：

```bash
node tests/run-all.js
```

## 六个页面

### 1. 发现页 `#/discover`

顶部问候 + `2026年9月19日，周六` + 数据版本号 → 搜索框 → 筛选 / 护航开关 → 今日焦点 → 截止雷达 → 机会卡片列表。

卡片包含：来源徽章、状态徽章、风险 / 待确认徽章、标题、摘要、时间 / 地点 / 对象 / 截止、
标签、推荐理由（护航模式下）、倒计时、收藏 / 报名 / 日历快捷操作。

- **移动端**：筛选是底部抽屉 —— 点「筛选」滑出，点遮罩 / ✕ /「查看结果」关闭，`Esc` 亦可关闭，
  打开时锁定背景滚动。
- **桌面端**：筛选是 260px 常驻侧栏（sticky），**不使用遮罩**，与列表并排显示。

### 2. 详情页 `#/detail/:id`

完整信息表格（时间、地点、参与方式、适用对象、条件要求、报名方式、报名截止、是否需要审核、
人数限制、费用、投入时间、来源可信度、标签）+ 双重倒计时 + 关联通知 + 风险横幅 +
新生护航推荐理由 + 我的备注 + 底部吸底操作栏。

### 3. 日历页 `#/calendar`

月视图（事件点按来源着色，报名截止为橙色方块，今日高亮）、点击日期查看当日事件、
冲突检测（针对收藏 / 报名 / 已加入日历的活动）、截止雷达侧栏。

### 4. 发布页 `#/publish`

三步分步表单 + 实时预览卡片 + 缺失项自动提示「待确认」+ 我的发布管理（编辑 / 下架）。
通过 `#/publish?edit=<id>` 直接进入编辑模式。

### 5. 我的 `#/mine`

数据概览（收藏 / 报名 / 提醒 / 发布）+ 六个标签页：我的收藏、我的报名/意向、我的提醒、
我的发布、浏览历史、新生模式设置（含筛选偏好摘要与清除本地数据）。

### 6. 新生引导 `#/onboarding`

四步选择：年级 → 兴趣（多选）→ 基础 → 每周可投入时间，完成后开启新生护航模式，
并预览基于该档案的推荐卡片。

## 路由表

| 路由 | 页面 | 参数 |
| --- | --- | --- |
| `#/discover` | 发现页 | — |
| `#/detail/:id` | 详情页 | `id`：种子编号（`01`—`26`）或本机发布 id |
| `#/calendar` | 日历页 | — |
| `#/publish` | 发布页 | 可选 `?edit=<id>` 进入编辑模式 |
| `#/mine` | 我的 | — |
| `#/onboarding` | 新生引导 | — |

路由实现见 `js/router.js`：模式串转正则（`#/detail/:id` → `^#\/detail\/([^/?]+)\/?$`），
支持查询串解析、订阅通知与 `replaceState` 无历史跳转。未知路由显示空状态并提供返回入口。

## 数据流与渲染机制

```
                    ┌───────────────────────┐
   用户操作 ───────► │ js/app.js 事件委托     │  一次 document 级监听
   (click/input)    │ data-action / -field   │  解析 → 分发到具体操作
                    └───────────┬───────────┘
                                │ 调用
                    ┌───────────▼───────────┐
                    │ js/store.js            │  唯一状态源 state
                    │ 收藏/报名/提醒/发布…   │  写入即持久化
                    └───────────┬───────────┘
                      ┌─────────┴─────────┐
                      ▼                   ▼
            ┌──────────────────┐  ┌──────────────────┐
            │ localStorage     │  │ IndexedDB        │
            │ 用户状态/档案/偏好│  │ 发布/备注/历史/草稿│
            └──────────────────┘  └──────────────────┘
                                │
                    ┌───────────▼───────────┐
                    │ js/views/*.render()    │  纯函数式：state → HTML 字符串
                    └───────────┬───────────┘
                                ▼
                        mainEl.innerHTML
```

**渲染约定**

1. 视图模块只做 `render(root, params)`，输出 HTML 字符串并整体写入 `#main`，不做增量 DOM 操作；
2. 所有交互通过 **`document` 级事件委托**统一处理，动态内容无需重复绑定监听器；
3. **倒计时不重渲染**：`tick()` 每 1000ms 只就地更新 `[data-countdown]` 元素的文本与样式类，
   因此页面不会每秒闪动，也不会打断用户滚动；
4. 交互触发的重渲染保持当前滚动位置（`keepScroll`），只有路由切换才回到顶部；
5. 任何单次渲染异常都会被 `try/catch` 捕获并降级为「页面渲染出错」+ 返回发现页，
   不会让整个应用白屏。

## 持久化方案

| 存储 | 键 / 库 | 内容 |
| --- | --- | --- |
| localStorage | `campusradar:userState:v1` | 收藏、报名、提醒、不感兴趣、日历、历史兜底、备注 |
| localStorage | `campusradar:profile:v1` | 引导档案与新生护航开关 |
| localStorage | `campusradar:preferences:v1` | 搜索词、筛选条件、排序方式 |
| localStorage | `campusradar:seedVersion` | 种子版本，用于启动时迁移检查 |
| IndexedDB | `campusradar` → `posts` | 本机发布 |
| IndexedDB | `campusradar` → `notes` | 用户备注 |
| IndexedDB | `campusradar` → `history` | 浏览历史（含 `visitedAt` 索引） |
| IndexedDB | `campusradar` → `drafts` | 发布页草稿 |

**启动流程**：读取 localStorage → 合并 IndexedDB（并按时间取较新者）→ 检查种子版本并提示迁移 → 渲染。

**容错设计**：

- 损坏的 JSON 不会让页面崩溃，会回退默认值并在控制台给出警告。
- 浏览器在 `file://` 下禁用 IndexedDB 时自动降级：本机发布与历史在会话内有效，
  并通过 Toast 明确告知用户；收藏、报名、提醒与设置仍保存在 localStorage 中。
- 重复初始化不会丢失内存中已有的发布（本地与 IndexedDB 结果按 id 合并）。
- **种子数据永远不会覆盖用户状态。**

## 筛选与排序规则

### 筛选维度

| 维度 | 选项 |
| --- | --- |
| 来源 | 学校/校内、学院、项目组、竞赛、学生自发、资料、补充通知、本机发布 |
| 类型 | 讲座、竞赛、招募、志愿、学习小组、约球、资料、补充通知、搭子、交流、其他 |
| 对象 | 全校、大一、大二及以上、本科生、不限专业 |
| 条件 | 零基础、无需报名、需预约、需审核、限人数 |
| 状态 | 今日、即将截止、报名中、已结束、长期、待确认、风险 |

筛选条件会写入 `campusradar:preferences:v1`，**刷新后保留**；已选条件以可单独移除的 chip 呈现。

### 排序算法

默认「智能排序」为加权评分（`js/utils/trust.js`）：

```
score = 新生友好度 × 0.42 + 截止紧急度 × 0.38 + 时间就近度 × 0.20
```

- **新生友好度**（0—100）：零基础可参加、无需报名、面向全校/大一、官方来源加分；
  每周投入 ≥ 6 小时减分；风险信息 −60、疑似推广 −34、待确认 −10。
- **截止紧急度**：≤ 6 小时 = 100，≤ 1 天 = 88，≤ 2 天 = 74，≤ 4 天 = 58，之后递减，已截止 = 6。
- **时间就近度**：越近越靠前，已过期为 0。

此外，高风险与疑似推广信息会被 `splitByRisk()` 分离到折叠区，**不参与主列表排序**。

自检过程中定位并修复的真实缺陷（都已回归覆盖）：

| 缺陷 | 根因 |
| --- | --- |
| Hash 路由 `#/detail/:id` 永远解析失败 | `String.replace` 的替换串里 `$&` 被当作特殊模式，`:id` 未转成捕获组 |
| 发布页草稿「刷新后继续填写」失效 | 草稿被双层包裹，恢复时取错层级 |
| 发布页整页白屏 | 渲染时的 `ReferenceError`（变量名写错） |
| 引导页兴趣选择被清空 | 每次渲染都从档案重新同步草稿，覆盖了当前选择 |
| 部分种子字段丢失 | 构造器白名单漏了 `deadlineNote` / `waitlist` / `people` / `timeText` |
| IndexedDB 不可用时发布丢失 | 重复初始化用空结果覆盖了内存中的发布 |
| **筛选面板遮挡整页** | 全屏遮罩规则写在媒体查询之外，被桌面端 `display: block !important` 激活 |

## 常见问题

<details>
<summary><b>双击 index.html 后打开是空白页？</b></summary>

请用 Chrome / Edge / Firefox / Safari 的较新版本打开。本项目使用普通 `<script>` 加载（而非 ES Module），
就是为了保证 `file://` 协议下可直接运行，不受 CORS 限制。若仍然空白，请打开控制台（F12）查看报错，
并确认 `css/`、`js/` 目录与 `index.html` 的相对位置没有被移动。
</details>

<details>
<summary><b>为什么电脑上显示的「今日」和题目给的 2026-09-19 不一致？</b></summary>

状态徽章（今日 / 即将截止 / 已结束）按**真实系统时间**判定，以保证倒计时始终有意义。
当系统时间与数据基准日差距较大时，「今日焦点」会自动回退为「数据基准日前后两天」并明确标注来源，
不会空白也不会编造信息（见 `tests/clocktest.js`）。
</details>

<details>
<summary><b>刷新后数据还在吗？</b></summary>

在。收藏、报名、提醒、日历、我的发布、备注、浏览历史、引导设置与筛选偏好都会保留。
如果浏览器在本地文件模式下禁用了 IndexedDB，页面会弹出提示：本机发布与历史仅在本次会话内有效，
其余数据仍由 localStorage 保存。
</details>

<details>
<summary><b>换个文件夹打开，数据怎么没了？</b></summary>

浏览器按「源」隔离本地存储。`file://` 下绝大多数浏览器把所有本地文件视为同一个源，因此移动文件夹通常不影响；
但若某些浏览器把每个文件路径当作独立源，或你用 `http://localhost:8000` 打开过，
则与 `file://` 属于不同源，数据不会共享。想固定数据，就固定用同一种方式打开。
</details>

<details>
<summary><b>「报名」会真的提交给主办方吗？</b></summary>

不会。所有报名、提醒、发布都是**纯前端模拟**，不会向任何服务器发送请求。
「报名状态」只是你自己在本机的标记，用于整理和规划。
</details>

<details>
<summary><b>怎样彻底清空数据？</b></summary>

「我的 → 新生模式设置 → 清除全部本地数据」（需二次确认），会同时清理 localStorage 与 IndexedDB。
也可以在浏览器开发者工具中删除名为 `campusradar` 的 IndexedDB 数据库与 `campusradar:*` 的本地存储键。
</details>

<details>
<summary><b>筛选项太多，点「筛选」后页面被挡住了怎么办？</b></summary>

这曾是一个已修复的 bug（遮罩规则写在了移动端媒体查询之外）。当前版本的规则是：
桌面端筛选是常驻侧栏、**不使用任何遮罩**；移动端是底部抽屉，点遮罩 / ✕ /「查看结果」/ `Esc` 都能关闭，
收起态不拦截点击。回归测试见 `tests/filtertest.js`。
</details>

<details>
<summary><b>如何新增一条种子数据？</b></summary>

在 `js/data/seed.js` 的 `RAW` 数组中追加一条 `make({...})` 调用即可：缺失的字段请留空（不要编造），
系统会自动计算 `missingFields` 并在界面上标注「待确认」。同时请把 `SEED_VERSION` 递增，
用户下次打开会收到一次「种子数据已更新，已保留你的数据」的提示。
</details>

## 技术选型说明

| 决策 | 理由 |
| --- | --- |
| 原生 HTML/CSS/JS | 题目硬性要求；也符合「校园场景下低门槛、可直接分发」的诉求 |
| 不用任何构建工具 | 双击即运行，无需 Node 环境；便于老师/同学直接查看与审阅 |
| 普通 `<script>` 而非 ES Module | ES Module 在 `file://` 下会被 CORS 拦截，无法双击运行 |
| IIFE + 全局命名空间 | 在无模块系统前提下保持文件拆分与依赖清晰，同时避免污染全局 |
| 渲染方式：字符串模板 + 事件委托 | 零依赖下性能足够；事件委托使动态内容无需重复绑定 |
| 倒计时就地更新而非重渲染 | 避免每秒重建整页 DOM 造成的闪烁与滚动跳动 |
| localStorage + IndexedDB 并存 | 轻量结构化状态用 localStorage（同步、简单）；体量较大或需独立管理的用 IndexedDB |
| 内联 SVG 图标 | 不依赖在线图标库，保持完全离线可用 |

## 开发约定

- **不编造数据**：缺失信息一律留空并由界面统一呈现，禁止用推测值填充。
- **新增交互**：按钮统一使用 `data-action="xxx"`，在 `js/app.js` 的委托分支中处理；
  表单字段使用 `data-field`；已选筛选 chip 使用 `data-filter`。
- **新增页面**：在 `js/views/` 下新建模块并挂载到 `CR.views.<name>`，
  提供 `render(root, params)`，然后在 `js/router.js` 的 `ROUTES` 与 `index.html` 的脚本列表中登记。
- **新增样式**：优先复用 `css/styles.css` 顶部的设计令牌，避免硬编码色值与间距。
- **改 CSS 媒体查询要当心**：桌面/移动的覆盖关系靠层叠顺序保证，
  全屏遮罩类规则必须写在移动端媒体查询内（`tests/filtertest.js` 会守住这一点）。
- **提交前自检**：运行 `node tests/run-all.js`，确保 273 项断言全部通过。
- **不要提交**：`node_modules/`、编辑器与系统产生的临时文件（已在 `.gitignore` 中排除）。

## 如何扩展

<details>
<summary><b>新增一个筛选维度</b></summary>

1. 在 `js/store.js` 的 `filterOpportunities()` 中加入你的判断分支，并在 `CONDITIONS` / `audienceKeys()` 中登记选项；
2. 在 `js/views/discover.js` 的 `filterPanel()` 里加一组 `chipGroup(...)`，并在 `activeChips()` 中登记回显；
3. 选项会自动写入 `campusradar:preferences:v1`，无需额外处理持久化。
</details>

<details>
<summary><b>接入真实后端接口</b></summary>

当前所有数据来自 `js/data/seed.js` 与 IndexedDB，没有任何网络请求。若要接后端：

1. 在 `js/store.js` 的 `init()` 中拉取远程数据，与种子数据按 `id` 合并（保留用户状态）；
2. 把 `setSignup` / `createPost` 等写操作改为「先本地写入、再异步同步」；
3. `js/views/*` 无需改动 —— 它们只依赖 `store` 暴露的数据形状。
</details>

<details>
<summary><b>新增一种来源类型或徽章配色</b></summary>

在 `js/utils/trust.js` 的 `SOURCE` / `TRUST` / `STATUS` 三个映射表中加一项，
再到 `css/styles.css` 增加对应的 `.badge--xxx` 配色即可，徽章与筛选会自动生效。
</details>

<details>
<summary><b>替换为真实通知提醒</b></summary>

`js/app.js` 的 `checkReminders()` 已实现到点检测与浏览器通知（`Notification`）。
接入 Service Worker 后即可做到页面关闭也能提醒；当前实现只在页面打开时提醒，这是刻意的简化。
</details>

## 开发环境备注（含 Watt Toolkit）

这些是开发过程中真实踩到的问题，记录下来以节省后来者的时间。

### 使用 Watt Toolkit（Steam++）加速时的表现

- Watt Toolkit 会在本机 **80 / 443** 端口启动透明反向代理来加速 GitHub，
  `git clone / fetch / push` 都能直接走通，**不需要给 git 配置任何代理**，
  也不需要设置 `HTTP_PROXY` / `HTTPS_PROXY`。
- 副作用：`curl.exe` 等直接使用 Windows Schannel 的工具可能报
  `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` —— 这是加速器环境下**证书吊销列表查不到**导致的，
  与被访问的仓库内容无关。遇到时可加 `--ssl-no-revoke`，或改用 `git` / `Invoke-RestMethod` 验证。
- 验证推送结果更可靠的方式是对比 **blob 哈希**，而不是下载文件：

  ```bash
  git rev-parse HEAD:README.md                    # 本地 Git 实际存储的内容
  git ls-tree origin/main -- README.md            # 远端指向的内容
  ```

  两者一致即代表推送成功（可用 GitHub API 的 `contents` 接口交叉验证）。

### 让命令不卡在认证上

自动化执行时建议设置，避免命令阻塞等待输入：

```bash
GIT_TERMINAL_PROMPT=0    # 需要凭据时直接失败而不是等待输入
GCM_INTERACTIVE=never    # 禁用 Git Credential Manager 的交互窗口
```

本项目使用 Git Credential Manager 存储凭据，推送一次后即可静默复用。

### Windows 上的两个小坑

- **换行符**：仓库已通过 `.gitattributes` 统一为 LF（`* text=auto eol=lf`），
  避免 Windows 下提交产生整文件差异。
- **PowerShell 5.1 不支持 `&&` / `||` / 三元 `? :` / here-string `<<`**，
  写多行提交信息请用 `git commit -F <文件>`，不要用 heredoc。
