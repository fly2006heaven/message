## 这是什么

校园里的机会分散在公众号、群聊、海报和口头通知里：截止时间藏在图片中、地点临时变更、有的需要审核、
有的来源可疑。新生尤其容易错过或踩坑。

**CampusRadar** 把校园活动、竞赛、招募、志愿、学习小组与资料聚合到一个可在浏览器离线运行的站点里，
重点解决四件事：

| 能力 | 具体表现 |
| --- | --- |
| **发现** | 今天、明天、近期可参加的机会一屏可见，支持搜索 / 五类筛选 / 智能排序 |
| **理解** | 来源、适用对象、报名截止、是否需要审核、是否有补充通知、信息是否缺失、是否存在风险 |
| **参与** | 收藏、报名 / 意向登记、设置提醒、加入日历、标记不感兴趣、复制信息 |
| **发布** | 学生可自主发布约球 / 搭子 / 招募 / 交流信息，并进入发现、筛选、日历等完整流程 |

所有判断都**只使用题目已提供的信息**：凡未注明的一律显示「未注明，请以主办方通知为准」，不做补全或猜测。

## 快速开始

```bash
# 方式一：直接双击
index.html

# 方式二：任意静态服务器（可选）
python -m http.server 8000     # 然后访问 http://localhost:8000
npx serve                      # 或使用任意静态服务器
```

无需 `npm install`、无需打包、无需联网。首次访问会自动进入新生引导页（`#/onboarding`），
也可以在地址栏直接输入任意路由，例如 `#/detail/01`。

## 六个页面

### 1. 发现页 `#/discover`

顶部问候 + `2026年9月19日，周六` + 数据版本号 → 搜索框 → 筛选 / 护航开关 → 今日焦点 → 截止雷达 → 机会卡片列表。

卡片包含：来源徽章、状态徽章、风险 / 待确认徽章、标题、摘要、时间 / 地点 / 对象 / 截止、
标签、推荐理由（护航模式下）、倒计时、收藏 / 报名 / 日历快捷操作。

### 2. 详情页 `#/detail/:id`

完整信息表格（时间、地点、参与方式、适用对象、条件要求、报名方式、报名截止、是否需要审核、
人数限制、费用、投入时间、来源可信度、标签）+ 双重倒计时 + 关联通知 + 风险横幅 +
新生护航推荐理由 + 我的备注 + 底部吸底操作栏。

### 3. 日历页 `#/calendar`

月视图（事件点按来源着色，报名截止为橙色方块，今日高亮）、点击日期查看当日事件、
冲突检测（针对收藏 / 报名 / 已加入日历的活动）、截止雷达侧栏。

### 4. 发布页 `#/publish`

三步分步表单 + 实时预览卡片 + 缺失项自动提示「待确认」+ 我的发布管理（编辑 / 下架）。
通过 `#/publish?edit=<id>` 直接进入编辑模式。

### 5. 我的 `#/mine`

数据概览（收藏 / 报名 / 提醒 / 发布）+ 六个标签页：我的收藏、我的报名/意向、我的提醒、
我的发布、浏览历史、新生模式设置（含筛选偏好摘要与清除本地数据）。

### 6. 新生引导 `#/onboarding`

四步选择：年级 → 兴趣（多选）→ 基础 → 每周可投入时间，完成后开启新生护航模式，
并预览基于该档案的推荐卡片。

## 种子数据

`js/data/seed.js` 内置 **26 条**完整数据，版本号 `2026.09.19-1`，基准日 `2026-09-19（周六）`。

- 数据**只读**：任何用户操作都不会改写种子数据。
- 每条记录显式携带 `missingFields`（缺失项数组），未提供的信息一律为 `null`。
- 全库唯一一处推算已双重标注：`13 科研助理招募` 题目只写「9 月 21 日截止」，
  代码按当日 `23:59` 计算，界面同时显示「题目仅注明 9 月 21 日截止，此处按当日 23:59 计算」。

### 关联关系

| 关系 | 处理方式 |
| --- | --- |
| `09` → `01` | 补充通知独立成卡，详情页「关联通知」并列展示，**不覆盖原文** |
| `20` → `03` | 同上 |
| `04` 已结束 | 状态为「已结束·预计 9 月 20 日传回放」 |
| `17` 资料 | 长期开放；`9/22` 标注为「网盘提取信息有效期，非报名截止」 |
| `19` 报名已截止 | 显示「报名已截止，可候补关注」 |
| `24` 高风险 | 红色左竖条 + 高风险横幅，降权至列表末尾并折叠 |
| `25` 疑似推广 | 橙色左竖条 + 疑似推广提示，降权并折叠 |

## 持久化方案

| 存储 | 键 / 库 | 内容 |
| --- | --- | --- |
| localStorage | `campusradar:userState:v1` | 收藏、报名、提醒、不感兴趣、日历、历史兜底、备注 |
| localStorage | `campusradar:profile:v1` | 引导档案与新生护航开关 |
| localStorage | `campusradar:preferences:v1` | 搜索词、筛选条件、排序方式 |
| localStorage | `campusradar:seedVersion` | 种子版本，用于启动时迁移检查 |
| IndexedDB | `campusradar` → `posts` | 本机发布 |
| IndexedDB | `campusradar` → `notes` | 用户备注 |
| IndexedDB | `campusradar` → `history` | 浏览历史（含 `visitedAt` 索引） |
| IndexedDB | `campusradar` → `drafts` | 发布页草稿 |

**启动流程**：读取 localStorage → 合并 IndexedDB（并按时间取较新者）→ 检查种子版本并提示迁移 → 渲染。

**容错设计**：

- 损坏的 JSON 不会让页面崩溃，会回退默认值并在控制台给出警告。
- 浏览器在 `file://` 下禁用 IndexedDB 时自动降级：本机发布与历史在会话内有效，
  并通过 Toast 明确告知用户；收藏、报名、提醒与设置仍保存在 localStorage 中。
- **种子数据永远不会覆盖用户状态。**

## 筛选与排序规则

### 筛选维度

| 维度 | 选项 |
| --- | --- |
| 来源 | 学校/校内、学院、项目组、竞赛、学生自发、资料、补充通知、本机发布 |
| 类型 | 讲座、竞赛、招募、志愿、学习小组、约球、资料、补充通知、搭子、交流、其他 |
| 对象 | 全校、大一、大二及以上、本科生、不限专业 |
| 条件 | 零基础、无需报名、需预约、需审核、限人数 |
| 状态 | 今日、即将截止、报名中、已结束、长期、待确认、风险 |

筛选条件会写入 `campusradar:preferences:v1`，**刷新后保留**；已选条件以可单独移除的 chip 呈现。

### 排序算法

默认「智能排序」为加权评分（`js/utils/trust.js`）：

```
score = 新生友好度 × 0.42 + 截止紧急度 × 0.38 + 时间就近度 × 0.20
```

- **新生友好度**（0—100）：零基础可参加、无需报名、面向全校/大一、官方来源加分；
  每周投入 ≥ 6 小时减分；风险信息 −60、疑似推广 −34、待确认 −10。
- **截止紧急度**：≤ 6 小时 = 100，≤ 1 天 = 88，≤ 2 天 = 74，≤ 4 天 = 58，之后递减，已截止 = 6。
- **时间就近度**：越近越靠前，已过期为 0。

此外，高风险与疑似推广信息会被 `splitByRisk()` 分离到折叠区，**不参与主列表排序**。

## 新生护航模式

开启后（引导页或顶部盾牌按钮或「我的 → 新生模式设置」）：

1. 每张卡片显示**推荐理由**，理由全部由已有数据生成：

   | 理由示例 | 数据来源 |
   | --- | --- |
   | 零基础可参加 | `beginnerFriendly === true` |
   | 面向全校 | `audience === 'all'` |
   | 今天 19:00 | 活动开始时间与当天一致 |
   | 无需报名 | `needSignup === false` |
   | 截止临近：05:12:33 | 截止时间在 24 小时内 |
   | 需预约，提交报名表不代表最终录取 | `needReview === true` |
   | 每周约 4 小时，符合你的时间预算 | `weeklyHours` ≤ 档案中的每周可投入时间 |

2. 排序切换为「新生友好度优先」时权重更高。
3. 详情页单列「新生护航模式推荐理由」面板，并标注「仅依据已提供信息」。

## 冲突与截止雷达

**时间冲突检测**（`js/utils/conflict.js`）：对收藏 / 报名 / 已加入日历的活动做区间重叠检测
（无结束时间按 30 分钟估算），按天分组展示。

内置可验证的冲突样例：**9 月 21 日 19:00 大学生科研入门分享会、19:00 Git 与 GitHub 零基础工作坊、
19:30 程序设计训练营补充通知（首次训练）** —— 日历页会显示「9月21日 有 3 个活动时间重叠」。

**截止雷达**：汇总所有带截止时间的条目，按时间升序，支持「含已截止」开关，
截止 ≤ 1 小时的条目倒计时带脉冲动效。

**关联通知合并**：`relations()` 依据 `relatedIds` 双向查找，补充通知与原文并列展示，绝不覆盖。

## 缺失、更新与风险处理

| 场景 | 界面表现 |
| --- | --- |
| 未提供信息 | 「未注明，请以主办方通知为准」 |
| 活动已结束但有回放 | 「已结束，预计 9 月 20 日上传回放」 |
| 补充通知 | 独立成卡 + 详情页关联展示，不覆盖原文 |
| 报名已截止但可候补 | 「报名已截止，可候补入场」+ 候补关注状态 |
| 需要审核 | 「提交报名表不代表最终录取，以审核通知为准」 |
| 学生自发但地点未定 | 「待确认，请以发起人通知为准」 |
| `24` 可疑兼职 | **高风险**红色横幅：不建议添加私人微信、转账或提供证件信息；排序降权至末尾并折叠 |
| `25` 商家推广 | **疑似推广**橙色提示：标题与正文不符且缺失时间地点；降低推荐权重并折叠 |

## 常见问题

<details>
<summary><b>双击 index.html 后打开是空白页？</b></summary>

请用 Chrome / Edge / Firefox / Safari 的较新版本打开。本项目使用普通 `<script>` 加载（而非 ES Module），
就是为了保证 `file://` 协议下可直接运行，不受 CORS 限制。
</details>

<details>
<summary><b>为什么电脑上显示的「今日」和题目给的 2026-09-19 不一致？</b></summary>

状态徽章（今日 / 即将截止 / 已结束）按**真实系统时间**判定，以保证倒计时始终有意义。
当系统时间与数据基准日差距较大时，「今日焦点」会自动回退为「数据基准日前后两天」并明确标注来源，
不会空白也不会编造信息（见 `tests/clocktest.js`）。
</details>

<details>
<summary><b>刷新后数据还在吗？</b></summary>

在。收藏、报名、提醒、日历、我的发布、备注、浏览历史、引导设置与筛选偏好都会保留。
如果浏览器在本地文件模式下禁用了 IndexedDB，页面会弹出提示：本机发布与历史仅在本次会话内有效，
其余数据仍由 localStorage 保存。
</details>

<details>
<summary><b>「报名」会真的提交给主办方吗？</b></summary>

不会。所有报名、提醒、发布都是**纯前端模拟**，不会向任何服务器发送请求。
「报名状态」只是你自己在本机的标记，用于整理和规划。
</details>

<details>
<summary><b>怎样彻底清空数据？</b></summary>

「我的 → 新生模式设置 → 清除全部本地数据」（需二次确认），会同时清理 localStorage 与 IndexedDB。
也可以在浏览器开发者工具中删除名为 `campusradar` 的 IndexedDB 数据库与 `campusradar:*` 的本地存储键。
</details>

<details>
<summary><b>如何新增一条种子数据？</b></summary>

在 `js/data/seed.js` 的 `RAW` 数组中追加一条 `make({...})` 调用即可：缺失的字段请留空（不要编造），
系统会自动计算 `missingFields` 并在界面上标注「待确认」。同时请把 `SEED_VERSION` 递增，
用户下次打开会收到一次「种子数据已更新，已保留你的数据」的提示。
</details>

## 技术选型说明

| 决策 | 理由 |
| --- | --- |
| 原生 HTML/CSS/JS | 题目硬性要求；也符合「校园场景下低门槛、可直接分发」的诉求 |
| 不用任何构建工具 | 双击即运行，无需 Node 环境；便于老师/同学直接查看与审阅 |
| 普通 `<script>` 而非 ES Module | ES Module 在 `file://` 下会被 CORS 拦截，无法双击运行 |
| IIFE + 全局命名空间 | 在无模块系统前提下保持文件拆分与依赖清晰，同时避免污染全局 |
| 渲染方式：字符串模板 + 事件委托 | 零依赖下性能足够；事件委托使动态内容无需重复绑定 |
| localStorage + IndexedDB 并存 | 轻量结构化状态用 localStorage（同步、简单）；体量较大或需独立管理的用 IndexedDB |
| 内联 SVG 图标 | 不依赖在线图标库，保持完全离线可用 |

## 开发约定

- **不编造数据**：缺失信息一律留空并由界面统一呈现，禁止用推测值填充。
- **新增交互**：按钮统一使用 `data-action="xxx"`，在 `js/app.js` 的委托分支中处理；
  表单字段使用 `data-field`；已选筛选 chip 使用 `data-filter`。
- **新增页面**：在 `js/views/` 下新建模块并挂载到 `CR.views.<name>`，
  提供 `render(root, params)`，然后在 `js/router.js` 的 `ROUTES` 与 `index.html` 的脚本列表中登记。
- **新增样式**：优先复用 `css/styles.css` 顶部的设计令牌，避免硬编码色值与间距。
- **提交前自检**：运行 `node tests/run-all.js`，确保 256 项断言全部通过。
- **不要提交**：`node_modules/`、编辑器与系统产生的临时文件（已在 `.gitignore` 中排除）。
